* **Next program to implement:** 118 (`07-finite-state-machines/118-moore-sequence-detector`)
* **Currently being implemented:** none
* **Tools required:** `sudo apt-get install -y iverilog yosys verilator`
* **Last full regression:** all 117 implemented programs (001-117) pass
  simulation; 114/117 pass Yosys generic synthesis (025, 031, and 085 are
  intentionally simulation-only, see their READMEs §13); lint is clean
  except for four accepted warnings (085's cross-coupled NOR gates,
  086's and 093's deliberately-inferred latches, and 114's provably-safe
  constant-truncation warning — see each program's README §13).
* **Category 06 (registers-and-counters) is complete** (098-117, 20/20
  programs): a parameterized parallel-load register with enable; SISO/
  SIPO/PISO shift registers and a 74194-style universal shift register;
  an 8-bit maximal-length LFSR built two ways (Fibonacci vs. Galois
  feedback), verified by an exhaustive 255-state visited-bitmap period
  check; up/up-down/loadable/modulo-N counters ($clog2-sized for
  arbitrary moduli); a BCD decade counter cascaded into a 3-digit
  000-999 counter via a combinational same-edge carry chain; a
  self-correcting one-hot ring counter (NOR-feedback recovery, verified
  by hierarchical-force injection of invalid states); a Johnson
  (twisted-ring) counter with a one-hot state decoder; a Gray-code
  counter (verified both against a reference and via a direct
  one-bit-Hamming-distance property check); a deliberately asynchronous
  ripple counter; even- and odd-ratio 50%-duty clock dividers (the odd
  case tracking the live clock signal for one middle cycle, derived and
  checked by hand before coding); and a fixed-period tick generator plus
  a runtime-programmable prescaler as the preferred clock-enable
  alternative to deriving new clock domains. Three genuine RTL bugs (not
  merely testbench bugs) were found and fixed during development, each
  documented in its own program's README: 113's ripple counter initially
  cascaded each stage on the wrong edge, producing a down counter instead
  of up (a classic, easy-to-get-backwards ripple-counter fact); 111's
  testbench assumed the wrong state-index numbering for the Johnson
  counter's decoder; and 115's testbench raced a delta-cycle glitch by
  waiting on a raw `posedge` of a signal combinationally derived from
  both a registered counter and the live clock, fixed by sampling at a
  settled instant after each real clock edge instead.
* **Category 05 (sequential-logic) is complete** (085-097, 13/13
  programs): a gate-level cross-coupled SR latch (Yosys generic
  synthesis intentionally skipped — its combinational feedback loop is
  flagged as a "logic loop" problem, not a real defect), a
  behaviorally-inferred D latch, an edge-triggered D flip-flop (this
  repository's canonical template), all three common reset styles
  compared side by side, a clock-enabled D flip-flop, JK/T/SR
  flip-flops (the SR variant with an explicit hold-on-invalid policy and
  status flag), a master-slave D flip-flop built from two D latches
  (verified against a plain behavioral reference), excitation-table
  flip-flop conversions (JK-from-D, T-from-D, and a D-from-JK round trip
  proven algebraically identical to plain D), a two-register-stage edge
  detector, a 3-stage pass-through pipeline (latency vs. throughput),
  and a sequential-circuit-analysis exercise using hierarchical `force`
  for exhaustive state-space verification. Several testbench bugs were
  found and fixed during development, each documented in its own
  program's README: 092's `s`/`r` left uninitialized before the first
  check plus a zero-delay race between assigning them and waiting on
  `@(posedge clk)` in the same time step; 095's edge detector itself
  (not just its testbench) originally compared a live unregistered
  signal against a single delayed register, producing only an
  unobservable delta-cycle glitch instead of a real pulse, fixed by
  adding a second register stage; and 096's pipeline latency check had
  an off-by-one between the loop's cycle counter and clock edges
  elapsed.
* **Category 04 (arithmetic-circuits) is complete** (062-084, 23/23
  programs): half/full adders and subtractors; a combined
  adder/subtractor with carry/overflow/zero/negative flags via
  two's-complement negation; flat and hierarchical (two-level)
  carry-lookahead, carry-select, carry-skip, and three-operand
  carry-save adders; a cascaded-digit BCD adder; a
  half-adder/half-subtractor-chain incrementer/decrementer; a
  linear-chain array multiplier; a Baugh-Wooley signed multiplier
  (correction terms derived algebraically, verified by hand for 2 bits
  and exhaustively for 4); a hand-derived Wallace-tree reduction
  multiplier; a parameterized radix-4 Booth multiplier; a combinational
  restoring-division array; a single-`case` 4-bit ALU and an 8-bit
  hierarchical ALU (separate arithmetic/logic/shift units, result mux,
  dedicated flag unit); Q3.4 fixed-point saturating add / rounding-
  saturating multiply; and an IEEE-754 single-precision floating-point
  adder (unpack/align/add-or-subtract/normalize-round, educational
  subset — normal numbers and zero only, no NaN/Infinity/subnormals,
  documented in that program's README §13). Three testbench bugs were
  found and fixed during development, each documented in its program's
  own README: 068's subtraction reference dropped the borrow bit by
  using Verilog's 4-bit-wrapped `a-b` instead of a widened-minuend
  computation; 075's decrement-mode `wrap` reference had an unneeded
  sign inversion; 083's multiply-rounding reference used round-half-
  away-from-zero instead of the design's documented round-half-up rule,
  disagreeing exactly at `.5` ties. A `generate`-loop-over-a-shared-
  vector Verilator `UNOPTFLAT` false positive recurred twice (075, 080)
  and was fixed both times by switching to a procedural `for` loop.
* **Category 02 (multiplexers-encoders-decoders) is complete** (032-045,
  14/14 programs): 2:1/4:1/8:1/N:1 muxes, 1:4/N demuxes, 2:4/3:8/N:2^N
  decoders, an 8:3 encoder, 4:2/N-bit priority encoders, a mux-based
  Shannon-expansion logic implementation, and a range-comparison memory
  address decoder.
* **Category 03 (combinational-logic) is complete** (046-061, 16/16
  programs): a 7485-style cascaded 4-bit comparator and a parameterized
  signed/unsigned comparator, parity generation/checking, binary/Gray
  conversion, a hex-to-7-segment decoder, binary-to-BCD (double dabble)
  and BCD-to-Excess-3 conversion, a one-hot-to-binary OR-tree converter,
  leading-zero counting (priority-scan vs. recursive-tree implementations
  cross-checked against each other), a recursive adder-tree population
  counter, a single-operator shifter and a `generate`-staged barrel
  shifter/rotator, a triple-modular-redundancy majority voter (fault
  injection covering both maskable single faults and unmaskable
  same-bit double faults), a thermometer-code converter with
  bubble-tolerant (population-count) decoding, and a Hamming(7,4)
  single-error-correcting codec. Two genuine RTL/testbench bugs were
  found and fixed during development: a per-bit cascade in the 046
  comparator that let a low-order bit override an already-decided
  higher-order comparison, and a shared testbench loop-index variable
  collision in 049 that hung a simulation; both are documented in their
  respective READMEs §9/§10.

## Project decisions

1. **Category order adjusted.** Multiplexers/encoders/decoders (`02`) come
   before general combinational logic (`03`) and arithmetic (`04`), because
   shifters, comparators and ALUs are built from them.
2. **Sequential arithmetic lives in `12-datapath-and-rtl`.** Shift-add and
   Booth multipliers, restoring/non-restoring dividers and square root are
   FSM + datapath designs, so they come after registers, counters and FSMs.
   Category `04` contains combinational arithmetic only.
3. **Global, stable three-digit numbering** across all categories (001–324
   planned). New programs are appended with the next free number.
4. **Verilog-2005** is the default language (`iverilog -g2005`). The only
   planned exception is `291-systemverilog-immediate-assertions` (`-g2012`),
   which exists specifically to show the difference.
5. **Default reset style:** asynchronous assert, active-low `rst_n`.
   Programs teaching other styles state it explicitly.
6. **Self-checking testbenches with a fixed pass/fail contract**
   (`TEST PASSED: n checks` / `TEST FAILED: …`), evaluated automatically by
   `scripts/run.py`. Simulation logs in READMEs are inserted by the script,
   never typed by hand.
7. **Synthesis check = Yosys generic `synth` + `check -assert`**, with
   inferred latches treated as failures unless the program is about latches
   (`ALLOW_LATCH=yes`). This is reported as *SYNTHESIS VERIFIED (Yosys
   generic synthesis)* and is not a timing/implementation sign-off.
8. **Program self-containment.** Each program folder contains every module it
   needs (for example, `full_adder.v` is copied into each adder program)
   so a learner can open, read and simulate one folder in isolation. Shared
   libraries were rejected because they would make early programs depend on
   later ones.
9. **Testbench helper models** (SRAM, sensors, bus slaves, protocol devices)
   live in `tb/` without the `tb_` prefix and are never synthesized.

## Limitations and blocked items

* No FPGA hardware testing (no board in the environment).
* Yosys generic synthesis does not check timing; any timing statements in
  READMEs are architectural reasoning, not sign-off results.
* Icarus Verilog does not model metastability; CDC programs demonstrate
  structure and protocol correctness, and explain what simulation cannot show.
